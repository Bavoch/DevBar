# 工程覆盖与可重复验收

产品覆盖以工程类型和可重复证据为单位，不以维护者电脑上的目录数量为支持承诺。个人项目盘点记录保留在本机 work/ 中，不随产品分发，也不作为新环境的验收结果。

## 检查顺序

1. `devbar doctor 项目目录 --json`：只读检查工程、目标、工具链和缺项。
2. `devbar init 项目目录 --target 目标 --plan`：审阅可推导的配置，不执行项目。
3. 在授权的隔离工程或明确选定的开发实例上 `sync`，随后只读 `status`。
4. 按实际平台检查界面、业务和数据保留；current 仅证明所声明源码、产物及运行实例。

贡献者基础回归执行 `python3 scripts/check-product.py`。完整适配器脚本见 [发布与验收](release.md)，各平台支持与待验边界见 [平台矩阵](platform-matrix.md)。基础检查不依赖维护者的个人项目。

## 常见覆盖缺口

- 开发服务器在线不等于桌面应用、手机应用或浏览器界面已更新。
- 模拟器与实体设备、不同 CPU 与系统版本分别验收。
- 跨工作树或跨仓库编排不能只用当前目录的摘要证明所有成员。
- 宿主插件必须从真实宿主中取得加载版本；不能用包装脚本在线代替。
- 缺少依赖、设备、签名、账号或运行证明时保留未确认状态。
- 一次性配置切换、库、素材和父应用组件不制造独立运行入口。

本地盘点工具接受显式 root/output，可用于自己的工程集合；输出包含路径、命令和环境信息，分享前应检查。不要将个人 work/ 报告提交到公开仓库。
