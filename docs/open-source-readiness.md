# GitHub 开源交付检查

DevBar 的目标是可独立安装、使用和贡献的 macOS 产品。管理本地开发项目是业务场景，产品本身不能依赖维护者的机器或个人项目。

## 本轮落实

- 更新配置失效的恢复入口与关闭自动更新入口；配置故障显示版本待确认。
- 历史记录仅提供当前项目、当前目标的可审阅草稿；保存前验证应用路径，独占创建文件，不覆盖已有配置，也不执行构建命令。
- 忽略关闭自动更新后到达的旧状态事件；自动更新成功使用严格版本已核对状态。
- 安装包附带帮助、变更记录和存在的许可证文件；面板关于/帮助与 CLI 版本查询。
- 贡献指南、问题与 PR 模板、安全报告说明、基础检查入口与 macOS GitHub Actions。
- 将个人工程验收记录移出公开文档；可选宿主测试改为显式输入，去除个人工程默认路径。
- 生成目录、个人测试工作区、常见凭据文件忽略规则；公开打包参数检查和 SHA-256 校验文件。

## 发布前仍需完成

| 事项 | 当前边界 |
| --- | --- |
| Git 仓库与远程地址 | 当前源码目录尚无 .git；本轮未创建远程仓库、提交、推送或发布 |
| 开源许可证 | 等待维护者选定 MIT 或 Apache-2.0；选定前不称为已授权开源的发行版 |
| 安全报告 | 仓库所有者需启用 GitHub private vulnerability reporting 或提供专用联系方式 |
| Developer ID / 公证 | 开发构建与公开发行分别验收；本轮不申请证书、不上传 Apple 公证 |
| CI | 已配置工作流，本地执行同一基础入口；GitHub runner 结果需首次推送后确认 |
| 安装与界面 | 离屏检查不替代用户首次安装、菜单操作和恢复对话框的人工验收 |
| 平台范围 | CPU、macOS 最低版本、设备与宿主分别验收，沿用 platform-matrix.md 的证据边界 |
| 升级机制 | 当前项目自动更新与 DevBar 自身公开发行升级是两条流程；尚无面向发行用户的在线自动升级承诺 |

首次公开提交前检查拟提交文件，不将 work/、个人路径、运行状态、日志或凭据加入版本管理。不要把本机旧验收记录作为 GitHub CI 的运行结果。正式发行按 release.md 完成签名、公证、Gatekeeper、版本和实际设备检查后，再发布对应产物与校验文件。
