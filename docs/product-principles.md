# 产品原则与适配验收

DevBar 按面向其他用户分发的独立 macOS 产品建设。当前机器上的项目用于提供真实案例，不作为安装路径、项目名称或环境默认值的来源。

- 能从工程与当前环境确定的信息自动获取。优先使用项目声明、锁文件、系统选中的工具链与标准 SDK 环境变量；不要求用户重复填写，也不静默替换项目声明的工具。
- 页面围绕用户当前任务组织。主入口、运行状态与下一步动作优先；技术详情按需展开，不平铺全部端口、适配器和诊断字段。
- 发现、运行、更新和功能验收分别提供证据。发现工程或脚本不等于能运行；命令在线不等于应用已更新；只有运行实例返回并核对真实版本后才报告 current。
- 同类环境判断共用入口。诊断与实际执行遵守同样的工具选择规则；不能因开发者机器恰好存在默认路径而掩盖配置错误。
- 未知类型与缺失条件明确暴露。无法确认入口时不生成猜测命令；单项目阻碍必须反映到整体审查状态，不以扫描完成掩盖失败。
- 自动化遵守已有授权与工程边界。只读发现不运行脚本、不安装依赖、不发布；不沿工作区软链接跨出扫描范围，不碰个人浏览器资料或无关进程。
- 分发包自包含，数据独立保存。移动应用后 CLI 与驱动仍可工作；本机同步、公开签名公证和各平台真实验收各自设门槛。
- 面板交互不等待发现任务。项目识别、进程表、运行目标和环境检查在后台生成状态快照；打开面板、重绘和按钮反馈只读取快照。受管停止直接核对已记录的进程身份，不等待全机发现；完成后立即更新目标状态，丢弃操作前的旧扫描结果。

## 自动接入与运行版本

- 自动接入可以省略配置，不能省略证据。优先复用工程入口、产物、包标识、工作区和宿主声明；显式配置保持优先，不批量写入猜测配置。
- 普通“运行”创建持续开发会话，优先使用项目原生 dev/watch/HMR；没有监听的源码入口自动重编译、重启。安装同步协议独立保留兼容，不能接管开发启动，面板不再提供单独的更新操作。
- 打开只激活实际开发实例，不回退到独立安装的应用；既有安装更新开关不能触发后台打包。没有可靠的源码更新路径或设备证据时明确说明限制，不把一次性启动当作热更新。
- 桌面开发启动按项目声明的 bundle identifier 识别同产品安装实例，先请求优雅退出再运行源码入口；退出被拒绝时明确失败。已有构建目录中的 `.app` 也不能冒充开发实例，原生开发 bundle 由真实目标会话负责归属。
- 开发命令的实际内容决定用途。构建后预览、直接运行产物和裸 Electron 启动不能因脚本名为 dev 就通过开发入口校验；开发失败的监督器允许直接重试，重启只处理所选目标。
- 核对范围与实际入口一致。静态页保留具体文档，插件预览保留 popup 路径，网页不采用编译器或调试端口；跨仓库子服务不能混进当前仓库的版本证明。
- 运行版本与业务健康分别表达。HTTP 服务在实际监听进程内测量源码，Worker 证据来自 workerd；非 HTTP 任务验证实际加载入口，不能据此宣称网络、数据库或业务任务成功。
- 保留运行数据与原有选择。原生更新校验完整应用内容，只替换程序；按身份和启动时间处理目标进程，失败与清理问题可见，不结束无关实例。
- 组件按归属验收。辅助程序随父应用构建核对；库、素材、备份不制造运行入口，异平台占位程序不能算当前平台支持。

## 每类工程的最低验收

| 工程 | 自动适配依据 | 必须另验的运行事实 |
|---|---|---|
| Web / API / Worker / 文档站 | 脚本、框架、包管理器、工作区子项目 | 真实入口、启动/停止隔离；严格同步需应用版本证明 |
| Electron / Tauri / Swift / macOS | 项目配置、原生产物、bundle identifier | 正确原生主进程、打开入口、更新与恢复 |
| iOS / Expo / Android / Flutter | 原生工程、框架脚本、选中 Xcode、SDK | 目标设备实际安装/启动/版本；模拟器与真机分别验收 |
| 浏览器插件 | Manifest / 构建框架与真实资源 | 独立无头浏览器内实际加载、更新与版本 |
| 微信小程序 | Taro / 工程配置与编译脚本 | 编译监听和开发工具里的实际效果分开；当前无完整内置宿主验收 |
| Blender / OMP / DSH | 宿主工程或插件声明 | 对应宿主实际加载和版本；不以本机脚本进程代替 |
| Compose / Windows | 容器配置或显式远程目标 | 实际容器/Windows 会话及应用版本 |
| 库 / 素材 / 备份 / 空目录 | 工程角色与边界 | 不要求独立运行，不为凑覆盖率制造启动入口 |

只读盘点用于找遗漏；隔离夹具用于可重复回归；真实设备、宿主及用户操作用于对应平台的最终验收。三者不能互相替代。

## 踩坑登记

- 开发服务反复退出而桌面仍显示旧版 → 同产品安装实例占用单实例锁，桌面子进程退出后监督器仍存活 → 启动前按确切产品身份退出安装实例，失败明确展示并允许重试；不能把监督器存活或 dev 脚本名当作开发成功。

- 默认路径存在却启动失败，或自定义 SDK 被误报缺失 → 检测固定 Xcode/adb 路径，与系统实际选中的工具链分叉 → Xcode 使用 DEVELOPER_DIR/xcode-select，adb 共用 PATH/ANDROID_HOME/ANDROID_SDK_ROOT 规则，模拟器从同一工具链定位。
- 工作区子目标漏报缺依赖 → 按冒号截断脚本名，把 dev:worker 当作 worker → 保留原脚本名，按最长完整后缀匹配子目标。
- inventory 显示 ready 但项目 doctor 已阻断 → 总体状态只看目录遍历错误 → 同时聚合项目配置错误与目标阻碍，返回 unconfirmed。
- 模拟器更新后完整内容核对失败 → simctl install 合并安装遗留旧可执行文件或签名 → 核对注册应用容器身份后可恢复地替换应用包，保留数据容器，不卸载、不忽略差异。
- Worker 模块已编译但服务没有就绪 → 在模块全局调用 crypto.randomUUID 被 workerd 禁止 → 实例身份在实际请求处理器内延迟生成，且版本响应必须来自 workerd，不以 Wrangler 控制进程代替。
- Worker 已启动却兼容日期、Node 兼容标记丢失 → 生成入口位于工程外，Wrangler 未沿用原配置 → 显式保留解析后的工程配置路径；私有证明路由遵守已有 run_worker_first 范围，不能被静态资产兜底。
- 非 HTTP Node 入口加载钩子递归溢出 → 在 load hook 内 require 内置 URL 模块再次触发同一 hook → 注册前解析并缓存依赖和入口 URL，钩子只处理加载结果。
- 组合任务失败后遗留后台守护进程 → 子进程 detached 后被重新托管，原进程树不再包含它 → 启动时记录 PID、用户及出生时间，停止/失败时按这些事实清理，清理失败明确报告。
## 多目标开发会话

同一项目的不同运行目标分别保存进程身份和开发监督状态，运行目标菜单展示各自状态并独立启停；项目列表仍汇总项目状态。停止只处理该目标持有的进程组及其可核验的原生会话，不根据同一项目目录推断其他进程归属。无法可靠归属的外部进程不能冒充某个受管目标，旧版未记录目标的运行会话需要先停止，再建立多个新会话。项目级停止遇到多个受管目标时要求明确指定目标。

- iOS 模拟器重复启动报设备已启动 → XcodeGen 生成的工程触发源码监督器再次重启 → 对使用 project.yml 的工程排除生成的 .xcodeproj，保留真实源码监听。
