# 产品原则

DevBar 面向使用 AI 构建个人产品的普通用户，是准备公开分发的轻量 macOS 本地项目运行管理工具。无需用户具备专业开发知识；也不能依赖维护者的目录、项目、工具链或全局 AI 规则。

## 最小主流程

添加项目 → 运行 → 打开 → 停止。菜单栏面板显示全部项目；运行中的优先，操作后按最近使用排序；顶部原生搜索框按名称、路径或状态即时筛选。失败给出重试与日志入口，缺少环境时说明所缺条件。

默认不展示命令、进程号、端口分类、源码哈希、适配器、版本证明、设备调试信息。项目名称、清楚的状态和必要的操作足够。日志、目录、其他运行方式与设置放在更多菜单；自定义命令按需展开。

不增加账户、后台服务、项目仪表盘、安装同步开关或远程管理入口。新功能必须解决主流程中的实际阻碍，不能只因为技术上可以实现而加入。

保留顶部操作区、搜索框及项目行右侧启停按钮的布局。内容使用 AppKit 原生 NSStackView、NSSearchField、NSTableView 和 NSButton；macOS 26 使用 NSGlassEffectView 承载，旧系统使用原生弹出面板材质。不绘制自定义按钮、颜色、字体或玻璃效果。项目的更多操作使用标准 NSMenu。

## 运行事实

- 添加、发现和诊断只读，不运行工程代码，不安装依赖，不部署。未添加的项目先根据运行事实显示；用户明确操作后才保留并读取该项目的启动方式。启动前检查仅限所选项目。
- 自动运行来自项目声明与确认的入口，不能仅凭脚本叫 dev 就执行构建、预览、发布或删除操作。
- 同一个项目的多个运行方式独立记录身份、启停与失败。某个失败不能掩盖仍在运行的其他方式。
- 编译、构建、安装与等待入口期间显示启动中；已知网页入口响应或实际应用会话出现后才确认运行。普通后台程序以真实进程为准，运行中不等于业务健康或代码版本已验收。失败后等待修复的监督进程不计为运行中的项目。
- 实时更新完全由工程自带工具负责。DevBar 不遍历源码、不注入热重载或构建启动器、不修改项目身份与签名；没有开发入口时明确要求配置。
- 不能确定入口就保留空设置并说明限制，不能制造猜测入口来提高覆盖率。库、素材、备份不需要独立运行。

## 控制边界

- 运行中的项目统一提供控制，不向用户区分启动来源。按真实项目入口、进程树、PID、出生时间、用户与可执行文件核对控制范围；不按目录、产品名称或共享进程组批量终止。
- 启动来源只影响内部停止策略：既有受管会话可清理自己的进程组，发现的会话仅操作已核验的具体 PID，桌面应用优先正常退出。普通运行不会结束或替换同产品安装版。
- 退出 DevBar 保留运行任务；项目运行期间不能移除它的管理记录。移除不删除项目文件。
- 普通运行独立于高级 `.devbar.json` 安装同步。自动识别不能推断安装位置、关闭安装版或执行安装替换。
- 进程发现、工具链检查、图标解析在后台完成，界面读取快照。停止先反馈，再异步处理，旧扫描不能恢复已停止状态。

## 交付边界

分发包自包含，数据独立保存，不植入全局 AI 调用规则或开机任务。保留既有配置，读取失败不覆盖原文件。扫描不跟随软链接跨越项目边界，配置读取拒绝特殊文件，不能因为一个项目阻塞其他项目的停止操作。

识别、隔离回归、真实设备、原生交互与签名公证是不同证据。任何一项都不能替代其他项。[发布检查](release.md) 与 [平台矩阵](platform-matrix.md) 记录公开发布前仍需完成的验收。
