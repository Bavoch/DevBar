# 应用启动与隐私权限归属

DevBar 只使用 macOS 公开系统机制。桌面应用与后台命令拥有不同的运行契约。

## 桌面应用

原生 `.app` 通过 `NSWorkspace.openApplication`（Launch Services）启动，核对返回的路径、bundle identifier 和可执行入口。应用自己声明和申请录屏等隐私权限。项目的普通启动按钮识别到桌面目标时，优先调用对应 macBundle 的构建、安装、启动流程；缺少可用的独立应用目标时明确报错，不退回直接执行桌面开发命令。原生构建运行、打开与更新后启动使用同一入口。

## 后台命令

构建、开发服务、进程同步及外部驱动通过公开的 `launchctl bootstrap gui/<uid>` 创建一次性用户会话 launchd 作业。系统直接启动 `/bin/zsh` 监督命令，DevBar 不作为其父进程，也不通过嵌入式启动器借出应用身份。作业没有登录注册、管理员权限或自动重启设置；退出后清理，崩溃残留在下一次启动前回收。

每次运行使用私有目录中的随机作业标识、PID 就绪握手及退出码回执，保留工作目录、环境、日志及真实进程身份。仅对已核对的 PID 与进程组停止；原有应用会话按自身身份管理。系统作业启动失败即报告错误，不回退到 DevBar 直接派生用户命令。

后台命令不是桌面应用。需要录屏、摄像头等交互隐私能力的程序必须以具有自身签名、标识与用途声明的 `.app` 运行；不把脚本包装成假应用，不把任意服务的启动成功宣称为隐私授权已验证。

## 分发与验证

源码与产品包不包含动态私有 API、权限责任 SPI 或私有启动组件。正式直接分发仍按发布脚本执行 Developer ID 签名、公证与支持系统矩阵验收；公开 API 不等于已经通过 App Store 审核，也不意味着沙盒内可以任意执行命令。

`verify_permission_ownership.py` 验证实际 Launch Services、launchd 作业、身份记录、日志、退出码、失败处理、清理及产品私有符号缺失。实际录屏归属另用目标应用的录屏操作、系统 TCC 日志与录制文件验证，不用普通启动 PID 检查替代。

已有授权不自动迁移、撤销或重置，旧进程重新启动后才使用新的启动流程。
