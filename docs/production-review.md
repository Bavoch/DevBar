## 运行控制修正

根据用户反馈，启动来源不作为用户概念。运行中项目统一显示“运行中”，都提供停止与重启。停止已发现的运行时只操作点击时捕获并再次核验的进程身份，不结束共享终端进程组；桌面应用请求正常退出。重启先校验启动方式，失败时保留原运行。未添加项目在用户停止、重启或设置后保留到列表。

修正验收：统一控制夹具验证真实面板停止与再次运行、标准 CLI 停止、重启前拒绝错误或未明确的运行方式、正常退出与拒绝退出的原生应用；终端、AI/MCP 工具、同目录无关监听及其他项目均保留。另验证失败的监督进程不掩盖健康运行、主停止覆盖所有已确认实例、项目级重启恢复原有多个运行方式。20 项检查全部通过，未对个人项目执行停止或重启。

## 本轮状态与流程复核

继续按“项目状态和控制与启动来源无关”检查，已修正：

- 网页准备期间、Swift/Rust/Go 编译期间、原生应用和插件等待真实会话期间保持“启动中”。普通无界面的程序按实际进程运行事实判断。程序正常结束显示停止，失败保留重试与日志。
- 终端或 AI 从其他目录启动绝对路径脚本时，按实际源码入口归属项目；路径含空格和虚拟环境无扩展名入口也纳入核验。
- 普通菜单栏环境能选择 nvm 默认 Node 与项目指定版本，子项目使用自己的运行目录；发现时不执行用户 shell 或工程脚本。
- 运行方式失效时保留现有运行，并提供重新选择入口；自定义命令不会错误套用第一个自动目标。
- 普通界面只展示运行阶段和行动提示，详细命令、路径、进程与错误信息留在日志。打开网页前重新核验入口的进程身份，避免使用已失效的入口。面板刷新不再执行版本探针或源码指纹检查。
- 原生应用正常退出与拒绝退出适用于所有启动方式。拒绝退出时保留应用及启动链，保存后可重试；专属无头插件浏览器按确切身份停止，不依赖它不支持的应用退出事件。
- CLI 对单一明确目标的既有运行返回运行状态，重复 sync 保留它；多个无法确认归属的运行方式要求确认，不制造停止状态。
